# Go next / continue: how any teammate's AI picks up, does and hands off work

## 0. continue(<name>) — how the five of us work (from 5 Nov 2026)

The plan is [MASTER_PLAN.md](MASTER_PLAN.md); every task on the board is assigned to one member (`reserved_for`), and every folder has one owner (§7 there), so two people never edit the same file. When a teammate types **`continue(<name>)`** (for example `continue(ramim)`), the AI:

1. `git pull --rebase` (stash or commit your own unfinished work first).
2. Finds the member: `python3 production/plan/board.py team`. Ids: `sadman`, `ramim`, `atik`, and two slots `member4` (QA and playtest lead) and `member5` (science, story and accessibility reviewer). A name that is not an id yet takes a free slot — ask which role they prefer if both are free, then `python3 production/plan/board.py rename-member member4 <name> --name "<full name>"`, commit `chore(team): <name> takes the member4 slot` and push. If no slot is free, stop and ask Sadman.
3. Reads the member's card (`production/plan/team/<card>.md`, shown by `board.py team`) and MASTER_PLAN.md §6–§7, §10–§11.
4. `python3 production/plan/board.py mine --by "<Name>/<AI>"` — finish those first. Then `python3 production/plan/board.py take --by "<Name>/<AI>" --count 5` (no `--tool`: it hands out only this member's ready tasks), commit `chore(board): claim <ids>` and push at once.
5. For each claimed task, steps 4–8 below, with one extra rule: **edit only the member's own folders.** A needed change in another member's folder becomes a task for them: `python3 production/plan/board.py add --milestone <M> --for <owner> --title "..." --prompt "<what, why, acceptance>" --paths <their folder> --by "<Name>/<AI>"`. Then continue with what you can do.
6. Tells the teammate what only a human can do: `python3 production/plan/board.py list --member <name> --tool human --status todo`.
7. One line after each task (id, done or blocked, commit); stop after about 8 tasks or when nothing is ready, with a short summary. Never leave claims behind.

A task of yours that is `blocked` with "Night shift parked the work on branch night/<id>" was started by Sadman's night shift: `release` it, then claim it and continue from that branch. Sadman's night shift (`production/tools/night_shift.py`) only takes Sadman's tasks.

The sections below are the original loop; `continue(<name>)` uses them with `--by "<Name>/<AI>"` and without `--tool`.

Two ways to start, both covered by this file:

- **"continue"** (the normal way to work): the AI pulls, claims a **chunk of up to 5 ready tasks** for its lane at once, pushes the claim, then does them one by one, verifying and pushing after each task. When the chunk is done it pulls and takes the next chunk, and keeps going until nothing is ready for its lane, it is blocked, or the session has done about 8 tasks (then it reports so the teammate can start a fresh session and say "continue" again). Saying "continue" again in the same session resumes the same loop.
- **"go next"**: the same steps for exactly one task.

Either phrase is the teammate's permission to claim, commit and push those tasks under their own GitHub account. It does not permit spending money, deleting other people's work, rewriting history, or skipping an approval a task asks for.

The board is `production/plan/tasks.json` (source of truth). `production/plan/BOARD.html` is the readable view, regenerated by every board command; open it in a browser to see everything.

### The "continue" loop in one screen

```bash
git pull --rebase
python3 production/plan/board.py mine --by "<name>/<lane>"     # anything already claimed by you? finish those first
python3 production/plan/board.py take --tool <lane> --count 5 --by "<name>/<lane>"
git add production/plan && git commit -m "chore(board): claim <ids>" && git push
# for each claimed task, in the order printed: board.py show <id> -> steps 4–8 below -> push
# chunk finished: git pull --rebase, then take the next chunk
```

Rules for chunks: take tasks from your own lane only; if a task in your chunk turns out to need something you cannot do (an approval, credits, another lane's work), `block` it with the reason and move on to the next one instead of stopping. Never sit on claims: if you stop before finishing a chunk, `release` every claimed task you did not start. Anyone may release a claim that `board.py stale --days 2` lists (nobody touched it for two days), after saying so in the commit message.

## 3. Claim it and push the claim at once

```bash
python3 production/plan/board.py claim M1-08 --by "<teammate name>/<tool>"
git add production/plan && git commit -m "chore(board): claim M1-08" && git push
```

If the push is rejected, `git pull --rebase` and run `board.py show M1-08`. If someone else claimed it first, `release` your copy and go back to step 2. Two people must never work on the same task.

**Merge conflicts in `production/plan/`:** board files are written one field per line, so different people's claims and results merge on their own. If git still reports a conflict there, open `tasks.json`, keep every other person's changes and your own (a task claimed by someone else stays theirs; release yours), save, then run `python3 production/plan/board.py html` to regenerate `BOARD.html` (never hand-merge it) and `board.py check`, then `git add production/plan && git rebase --continue`.

## 4. Read before working

1. `AGENTS.md` (rules every AI follows) and `PRODUCTION_HANDBOOK.md` sections 2–4 (canon, locked decisions, story facts).
2. The task prompt (`board.py show <id>`) and every file in its **read first** list. The `execution/` prompts it names were written on 27 Oct: trust the board task and the current code where they differ.
3. Recheck the current code for what the task touches. Reuse existing services; do not build a second version of something that exists.

## 5. Do only that task

- Work inside the task's **owns paths**. If you must touch another area, keep the change minimal and say so in the evidence.
- Canon is not negotiable: English only in the game (no Bangla script), plants never have faces, no NASA logos, the Moon science rules, story text word for word, numbers from `game-design/08_PUZZLE_DESIGNS.md`.
- Gameplay values live in data files, not code.
- Credits (Tripo, Meshy, ElevenLabs, Veo): only when the task says so, after any approval it requires, with the balance checked and each generation logged in `production/AI_PROMPT_LOG.md`. Never buy anything.
- New characters and hero props need the user's approval of the 2D sheet before 3D credits are spent.

## 6. Verify

```bash
game/tools/run_tests.sh        # every suite must pass; set GODOT=... on Windows/Linux
```

Godot exits 0 even when a test script fails to load, so use this runner, never a bare exit code. Anything a player sees (UI, rooms, cutscenes) needs screenshots in `production/qa/evidence/` named after the task id. Generated assets must pass the asset gate (`production/tools/verify_gate.py`).

## 7. Record it

- Add a row to `production/AI_PROMPT_LOG.md` for the AI work in this task (tool, model, what it did, prompts or the task id, files). The competition requires every AI tool and its prompts to be disclosed.
- If the task changes project status or a decision, add one dated line to `PRODUCTION_HANDBOOK.md` §10 (status) or §3 (decision).
- Found new problems? Add them as new tasks in `tasks.json` (next free id in the milestone, full prompt with repro and acceptance), then `board.py check`.

## 8. Mark done and push

```bash
python3 production/plan/board.py done M1-08 --evidence "run_tests.sh 25/25; production/qa/evidence/M1-08_*.png"
git add -A <the task's paths> production/plan production/AI_PROMPT_LOG.md
git commit -m "feat: interactive P-01 panel" -m "Task: M1-08"
git push
```

- Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`), with the task id in the body.
- Commit under the teammate's own GitHub account; different authors show the judges real teamwork. On Sadman's machine that is `sadmanqt`.
- **No AI co-author or "Generated with" lines** in commits or PRs; AI use is disclosed in the AI log instead.
- If you cannot finish: `board.py block <id> --reason "<what is missing and who can unblock it>"`, push, and stop.

## 9. Report, then continue or stop

- **"go next":** tell the teammate in a few lines what changed, the evidence, anything they must do (approvals, uploads), and the next ready task id for their lane. Stop.
- **"continue":** after each task, one line to the teammate (task id, done or blocked, commit). Then go on with the next task in your chunk; when the chunk is done, `git pull --rebase` and `take` the next one. Stop and give a short summary when nothing is ready for your lane, when you have done about 8 tasks in this session (a fresh session keeps quality high: the teammate starts one and says "continue" again), or when the teammate tells you to stop. Never leave claimed tasks behind when you stop: finish or `release` them, and push.
