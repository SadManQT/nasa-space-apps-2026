# Go next: how any teammate's AI picks up, does and hands off one task

When a teammate says **"go next"** (or pastes the prompt from the board), the AI follows these steps for exactly one task. Saying "go next" is the teammate's permission to claim, commit and push that one task under their own GitHub account. It does not permit spending money, deleting other people's work, rewriting history or skipping an approval the task asks for.

The board is `production/plan/tasks.json` (source of truth). `production/plan/BOARD.html` is the readable view, regenerated by every board command; open it in a browser to see everything.

## 1. Sync

```bash
git pull --rebase          # stash or commit your own unfinished work first
```

## 2. Pick the task

Use your own lane name:

| Lane | Who | Strengths it gets | Recommended model / effort |
|---|---|---|---|
| `claude` | Claude Code (incl. Opus thinking) | design docs, data and science mapping, generation pipelines (Tripo, Meshy, ElevenLabs), orchestration, video scripts | Opus, default effort |
| `codex` | Codex / ChatGPT (Plus plan: low limits) | short, targeted jobs: bug hunts, code review, one hard fix | `gpt-6.1-sol` medium; high only for tricky bugs. Long coding sessions go to Antigravity instead |
| `antigravity` | Antigravity (Pro plan) | long coding sessions, UI panels, visual verification with screenshots, game-feel | Gemini 4 Argon medium for long UI sessions; high for the Mission Table (P-02) and Mission Trainer; Claude Opus 5.5 high for science/data/docs; Claude Sonnet 5.5 medium for bulk content |
| `muse` | Muse AI | Blender: terrain, environment kits, clean-up, lighting, renders | Muse default |
| `gemini` | Gemini (Argon) | `any` tasks, Veo cutscenes, image concepts and paint-overs, research | Gemini 4 Argon medium |

Any AI may also take `any` tasks, or run `next` with no `--tool` to see every ready AI task.

```bash
python3 production/plan/board.py next --tool codex
```

It prints the first **ready** task for that tool: status `todo`, all dependencies `done`, ordered by milestone (M0 → M1 → M2 → M3), then priority. If it lists a task already `in_progress` that is yours, finish that first. `human` tasks are never taken by an AI; tell the teammate about them instead.

## 3. Claim it and push the claim at once

```bash
python3 production/plan/board.py claim M1-08 --by "<teammate name>/<tool>"
git add production/plan && git commit -m "chore(board): claim M1-08" && git push
```

If the push is rejected, `git pull --rebase` and run `board.py show M1-08`. If someone else claimed it first, `release` your copy and go back to step 2. Two people must never work on the same task.

## 4. Read before working

1. `AGENTS.md` (rules every AI follows) and `PRODUCTION_HANDBOOK.md` sections 2–4 (canon, locked decisions, story facts).
2. The task prompt (`board.py show <id>`) and every file in its **read first** list. The `execution/` prompts it names were written on 27 Oct: trust the board task and the current code where they differ.
3. Recheck the current code for what the task touches. Reuse existing services; do not build a second version of something that exists.

## 5. Do only that task

- Work inside the task's **owns paths**. If you must touch another area, keep the change minimal and say so in the evidence.
- Canon is not negotiable: English only in the game (no Bangla script), plants never have faces, no NASA logos, the Moon science rules, story text word for word, numbers from `game-design/08_PUZZLE_DESIGNS.md`.
- Gameplay values live in data files, not code.
- Credits (Tripo, Meshy, ElevenLabs, Veo): only when the task says so, after any approval it requires, with the balance checked and each generation logged in `production/AI_PROMPT_LOG.md`. Never buy anything.
- New characters and hero props need the user's approval of the 2D sheet before 3D credits are spent.

## 6. Verify

```bash
game/tools/run_tests.sh        # every suite must pass; set GODOT=... on Windows/Linux
```

Godot exits 0 even when a test script fails to load, so use this runner, never a bare exit code. Anything a player sees (UI, rooms, cutscenes) needs screenshots in `production/qa/evidence/` named after the task id. Generated assets must pass the asset gate (`production/tools/verify_gate.py`).

## 7. Record it

- Add a row to `production/AI_PROMPT_LOG.md` for the AI work in this task (tool, model, what it did, prompts or the task id, files). The competition requires every AI tool and its prompts to be disclosed.
- If the task changes project status or a decision, add one dated line to `PRODUCTION_HANDBOOK.md` §10 (status) or §3 (decision).
- Found new problems? Add them as new tasks in `tasks.json` (next free id in the milestone, full prompt with repro and acceptance), then `board.py check`.

## 8. Mark done and push

```bash
python3 production/plan/board.py done M1-08 --evidence "run_tests.sh 25/25; production/qa/evidence/M1-08_*.png"
git add -A <the task's paths> production/plan production/AI_PROMPT_LOG.md
git commit -m "feat: interactive P-01 panel" -m "Task: M1-08"
git push
```

- Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`), with the task id in the body.
- Commit under the teammate's own GitHub account; different authors show the judges real teamwork. On Sadman's machine that is `sadmanqt`.
- **No AI co-author or "Generated with" lines** in commits or PRs; AI use is disclosed in the AI log instead.
- If you cannot finish: `board.py block <id> --reason "<what is missing and who can unblock it>"`, push, and stop.

## 9. Report and stop

Tell the teammate in a few lines: what changed, the evidence, anything they must do (approvals, uploads), and the next ready task id for their tool. One task per "go next".
