## Proven causes and changes

1. **Review-grade CPU skinning in the gameplay hot loop.** `game/scripts/player/locomotion_pose.gd:118` and `:184` formerly called the full `FootSlide.sample()` twice per character per physics tick. `game/scripts/review/foot_slide.gd:119` transforms every boot vertex, allocates per-surface position/history arrays, and calculates velocity/contact statistics. IK consumes only the two minimum heights. With five characters this repeatedly exceeded the CPU frame budget. Added `sample_heights()` at `foot_slide.gd:97`: flat packed arrays, every original boot vertex/influence retained, and only the world-space Y row evaluated. IK calls that path now; the full review sampler remains available. Full-cast isolated per-call p95 fell **3.839 → 0.692 ms**. Both height queries remain; skipping the post-rotation query would change foot clearance.

2. **Synchronous raw glTF decoding repeated on every room reconstruction.** `game/scripts/campaign/chapter1_campaign.gd:448` rebuilds the room; `game/scripts/world/campaign_room.gd:280` loads each model. `game/scripts/asset_geometry.gd:20` uses `GLTFDocument.append_from_file()` / `generate_scene()` with uncompressed embedded images. The old player duplicated that same importer. Added an **8-entry LRU** of parsed PackedScenes (`asset_geometry.gd:7`), invalidated by source modification time, and routed character loading through it (`player_controller.gd:66`). Skeletons and node state are instantiated independently; immutable geometry/textures are shared. Repeated greenhouse construction fell **336.413 → 2.229 ms**. Source GLBs, texture resolution, shaders and outlines are unchanged. Evicted scenes can still be held by live instances; the cap bounds cached scene count, not total live memory.

3. **Fresh gait analysis during character construction.** `game/scripts/player/locomotion_clips.gd:122` samples each gait at 120 Hz and performs full boot/contact skinning to derive speed and cycle boundaries. All characters did this synchronously in `_ready()`. Five tiny JSON files in `game/resources/player/gaits/` now hold exactly those derived results; `locomotion_clips.gd:69` validates the source SHA-256 and bake version before using them. Missing/stale bakes fall back to the original analysis. Cubic cycle generation and all tuning remain unchanged. Bake precision uses full-precision JSON. Rebuild with `Godot --headless --path game --script res://tools/bake_locomotion.gd`; increment BAKE_VERSION if measurement/cycle algorithms change. The optional source path flows through `player_animation.gd:44` and `player_controller.gd:91`. No design arithmetic moved into code.

## Round 2: Per-System CPU Breakdown, Optimizations, and Rendered Verification

### 1. Root causes proven by the Round 2 sub-system timer breakdown ([cpu_r2_before.json](evidence/perf_2026-11-04/cpu_r2_before.json))

1. **Redundant per-frame boot height skinning and bone pose dirtying in `LocomotionPose` and `FootOrientation`.**
   - In `game/scripts/player/locomotion_pose.gd`, `_update_feet()` and `_clear_swing_feet()` previously called `boot_probe.sample_heights()` twice per character per physics tick (10 full-cast calls/tick = **3.516 ms** p50 in `boot_sample_heights_x2` plus **5.681 ms** p50 in `locomotion_pose_gd`), even when both feet were locked in stance (`locked[0] and locked[1]`) or only one foot was swinging.
   - `LocomotionPose._process_modification_with_delta()` also called `LocomotionClips.bone()` 4 times per character per frame and unconditionally called `rig.set_bone_pose_rotation()` / `set_bone_pose_position()` on hips, spine, chest, neck, head, thighs and shins, while `FootOrientation` unconditionally called `rig.set_bone_pose_rotation()` on both feet every frame—dirtying all 5 character skeletons and forcing redundant skinning/modifier re-evaluation.
   - In `game/scripts/review/foot_slide.gd`, `sample_heights()` iterated dynamic sub-range slices per vertex (`for k in range(start, stop)`). Pre-baking the 3 primary boot bone weights (`Leg`, `Foot`, `ToeBase`) into flat `PackedVector3Array`s (`_side_p0`, `_side_p1`, `_side_p2`, `_side_w`) with an exact fallback for extra influences, adding a `side_filter: int = -1` parameter so single-foot queries only evaluate one boot (~135 vertices instead of ~270), and caching `_boot_cache` by mesh/skin RID + bone count reduced cold `FootSlide.setup()` from ~48 ms/character to ~4 ms (warm `setup()` ~0.01 ms) and cut `locomotion_pose_gd` in the 5-character room from **5.681 ms → 0.474 ms** p50 (**12.0x** speedup).

2. **Per-tick $O(N^2)$ campaign target/gate queries in `Chapter1Campaign._physics_process()`.**
   - `game/scripts/campaign/chapter1_campaign.gd:235` called `nearby_target()` every physics tick (**0.512 ms** p50 in the Greenhouse, **0.310 ms** p50 in Commons). Inside `nearby_target()`, iterating over interactive nodes called `target_completed(target_id)` on each node, which in turn called `route.gate_status()`, `director.snapshot()`, `route.snapshot()`, and `targets_for_current_scene()` repeatedly per node.
   - Computing `gate_status`, `director.snapshot()`, and a completed-target dictionary once per `nearby_target()` call cut `campaign_nearby_target` to **0.032 ms** p50 in the Greenhouse (**16.0x** speedup) and **0.058 ms** p50 in Commons.

3. **Unconditional physics raycasts in `PlayerController._update_gaze()`.**
   - `game/scripts/player/player_controller.gd:155` called `nearest_interactable()` (which fires physics raycasts/group scans) every frame even when `attention_target` was already valid. Guarding the fallback scan behind `if not is_instance_valid(target)` eliminated redundant per-frame raycasts.

4. **Room-transition asset eviction, repeated mipmap readbacks, and cold route/profile setup.**
   - Increasing `AssetGeometry.CACHE_LIMIT` from `8` to `16` (`game/scripts/asset_geometry.gd:7`, within the `[4, 16]` bound enforced by `test_performance_runtime.gd`) keeps all 5 cast GLBs plus room props resident across room rebuilds.
   - Tagging mipmapped `ImageTexture`s with `mipmaps_ready` metadata in `ToonMaterials._ensure_mipmaps()` (`game/scripts/toon_materials.gd:79`) avoids calling `texture.get_image()` on already-processed textures.
   - Caching prepared `AnimationLibrary`, `gaits`, and `measurements` by `source_path` + mtime in `LocomotionClips` (`game/scripts/player/locomotion_clips.gd`), caching parsed `chapter1_base.json` in `ExpeditionSimulation._profile_cache` (`game/scripts/simulation/expedition_simulation.gd`), and adding `skip_initial_scene: bool = false` when `restore_session()` immediately restores a snapshot (`chapter1_campaign.gd`, `chapter1_route.gd`, `chapter2_route.gd`, `extended_campaign_route.gd`) cut `garden_rebuild` from **17.648 → 2.020 ms** (headless CPU) and **124.0 → 11.8 ms** (rendered), and cut `forecast_target_on_change` from **3.880 → 2.318 ms** p50.

### Loading flow and bounded main-thread work

- `AssetGeometry.request()/prepare()` uses `ResourceLoader.load_threaded_request()`, polls `load_threaded_get_status()` across frames, and calls `load_threaded_get()` **only after LOADED**. A custom `.lla_gltf` virtual resource suffix bypasses editor remapping while retaining exactly the original raw GLB decoding settings. The worker returns a `GLTFState` and its original `GLTFDocument`; using a fresh document for `generate_scene()` would omit its mesh-conversion extensions. Scene generation, instancing, packing, freeing and all scene-tree changes remain on main. The 16-scene LRU remains bounded; active room assets and plant variants are pinned against look-ahead eviction.
- `PreparationJob` uses `WorkerThreadPool` for content validation and animation resource preparation, following [Godot’s resource/scene thread-safety boundary](https://docs.godotengine.org/en/latest/tutorials/performance/thread_safe_apis.html). It passes no live Nodes to workers. Source clips are read-only, processed copies are private, and libraries are published after completion. Missing/stale gait bakes use the original measurement algorithm in a main-thread coroutine, yielding every four measurement poses; they cannot silently reintroduce synchronous full-gait analysis.
- `LoadPreparation` starts the five cast actors, first Commons/Garden assets, scene resources, portraits and opening voice resources while the title is displayed. Scenes, imported textures and audio use threaded resource requests and a 64-entry strong-reference cache. The next authored scene's room and voice files are prepared while the current scene remains playable (including the walk to its exit).
