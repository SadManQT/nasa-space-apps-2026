# M1-102 — Session crew setup in the campaign snapshot

For Ramim (saved Solo/Class UI, M1-37) and Atik (runtime bridge). Code: `game/scripts/core/`. Tests: `game/tools/test_session_crew.gd`.

## Schema

Optional top-level snapshot key (schema version stays 3):

```
"crew": {"mode": "solo" | "class", "players": int}
```

- Exactly two keys, `mode` and `players`; any other key is rejected.
- `solo`: players == 1. `class`: players 2, 3 or 4 (`CampaignState.CREW_PLAYER_RANGE`).
- `players` must be a finite whole number. `2.0` is accepted (JSON saves load numbers as floats) and read back as the int `2`. Strings, booleans, `2.5`, `NAN`, `INF`, negatives and out-of-range counts are rejected.
- Mode is case-sensitive: `"Solo"` is rejected.
- A snapshot with no `crew` key (every save before M1-102) is valid and reads as Solo/1.

## Signatures

`CampaignState` (`game/scripts/core/campaign_state.gd`):

```gdscript
const CREW_PLAYER_RANGE := {"solo": [1, 1], "class": [2, 4]}
const DEFAULT_CREW := {"mode": "solo", "players": 1}
static func crew_problem(crew: Variant) -> String          # "" when valid, else the reason
static func crew_of(snapshot: Dictionary) -> Dictionary    # {"mode": String, "players": int}; Solo/1 when absent
```

`validate_snapshot()` (and so `is_compatible()` and `CampaignDirector.restore_snapshot()`) rejects a snapshot whose `crew` fails `crew_problem()`.

`CampaignDirector` (`game/scripts/core/campaign_director.gd`):

```gdscript
func new_campaign(content_revision: String = "", crew: Dictionary = {"mode": "solo", "players": 1}) -> Dictionary
func crew() -> Dictionary                                   # {"mode": String, "players": int}
```

## Behaviour

- The crew is chosen once, at New Expedition: `new_campaign(rev, {"mode": "class", "players": 3})`. There is no setter mid-session; to change it, start a new expedition.
- Invalid crew: `new_campaign` returns `{}` before touching state, and `restore_snapshot` returns `accepted: false`. Both leave the Director's state and checkpoint unchanged.
- The crew rides inside the snapshot, so saves, `restore_snapshot`, `restore_checkpoint`, pause/resume and commits carry it unchanged. A Class start differs from a Solo start only in `crew`; resources, revision, receipts and checkpoint are identical.
- No dependency on `game/scripts/crew/crew_modes.gd`. The parked `set_crew` (8a792c1) was not ported.
