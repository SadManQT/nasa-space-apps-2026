# M1-37: Four-player Class mode on one machine (11 Nov 2026)

Built on the landed M1-102/M1-103 contract (`Main._start_new_expedition(crew)`, `Chapter1Route.team_plan_view` / `sign_team_plan`). No network play. Solo is unchanged.

## What was done
- **Solo / Class choice on New Expedition.** `game/scenes/ui/crew_choice_overlay.tscn` + `game/scripts/ui/crew_choice_overlay.gd`: SOLO · 1 PLAYER, CLASS · 2 / 3 / 4 PLAYERS (each with its seat plan), BACK · ESC. `game/scripts/main.gd` now connects the title's `new_expedition_requested` to `_choose_crew()`, which shows the overlay and then calls `_start_new_expedition(crew)`. `main_menu.gd`/`.tscn` are untouched; the zero-argument `_start_new_expedition()` still starts Solo.
- **Role data, not code.** `game/resources/campaign/content/crew_modes.json` (ported from `night/M1-37`, trimmed): role names, duties, accents, seat plans (Mei and Rafi never share a seat), and every hand-off, table, team-plan, menu and print line. Role facts stay in `p02_mission_table.json`. Reader: `game/scripts/classmode/crew_modes.gd` (`CrewModes`; validation stays in `CampaignState.crew_problem`).
- **Privacy hand-off.** `game/scenes/ui/role_card_handoff.tscn` + `game/scripts/ui/role_card_handoff.gd` (ported): a cover ("Pass this screen to Player 2. Everyone else, look away.") that shows no facts, then the reveal over an opaque backdrop, then HIDE · PASS ON to the next holder.
- **Class Mission Table.** `game/scripts/ui/mission_table_panel.gd` reads the crew from `route.director().crew()`. In Class the crew-notes column shows only holder, duty and status (NOT READ YET / READ PRIVATELY / SHARED); READ PRIVATELY and PASS THE NOTES ROUND open the hand-off; sharing is refused until the note was read privately. Lock in opens the **team plan**: plan line per shift, the forecast, and one SIGN AS row per role. Each signature calls `route.sign_team_plan(role, target, selection)` with the exact selection from `route.team_plan_view`; the operator's LOCK IN stays disabled until the route lists all four signatures, and the route itself still refuses an unsigned commit. Solo rendering and flow are unchanged.
- **Printable role cards.** `production/tools/build_role_cards.py` (ported) builds `docs/classroom/role_cards/` (cover sheet + four A5 cards as PNG, plus one PDF) from the same two JSON files. Regenerated this session; visually checked (English only, no logos, "not NASA-endorsed" footer).
- Not ported from the branch, as instructed: its `campaign_state.gd` / `chapter1_campaign.gd` setters, its own sign-off storage in `p02_mission_table.gd`, the HUD and settings-panel changes. `chapter1_campaign_hud.gd` was not edited.
