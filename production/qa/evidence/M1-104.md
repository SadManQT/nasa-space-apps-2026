## How the selected-input bridge should read it

1. A panel shows `choices[choice_id].options` for the current `investigation` entry. The player picks; nothing is prefilled.
2. A choice with `action` is a puzzle command. Put the chosen `value` into the payload under `payload_key` (P-04 tokens: `{"value": ...}`). For P-03 `prediction`, send `{prediction, reason, future_test}` from the three field lists. Send it through the existing route (`chapter2_route` → `preview_action` / `commit_action`). The script stays the authority: a wrong P-04 token is rejected by `P04RecorderReconstruction.preview_action`, and the test proves every `correct` flag agrees with that script.
3. A choice without `action` is a teaching check (structures, transfer design, boundary order, weather, schedule, trial stage, checksum meaning). Show its `feedback` on a wrong pick, then let the player pick again. It never charges a resource. The physical target (`target_id`) still commits through the gate catalog.
4. Show `feedback` for refusals the script returns, and `hints[group]` tiers on request (hints never change endings).
5. Today the gate catalog's `payload_defaults` hold the answers. The test asserts that those defaults are `correct` options here. Removing the defaults so the player's selection is used is Atik's M1-105 bridge and Ramim's panel work; this task does not change it.
