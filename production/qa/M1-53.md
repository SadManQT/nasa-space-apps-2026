Ports the earlier night-codex attempt (parked on `night/M1-53`, no longer merging
cleanly) onto current main, tightens two stale-owner paths, and runs the full

## What could wait forever (findings)

| Wait | Before | Now |
|---|---|---|
| `PreparationJob.finish()` (content validation, gait clips) | polled `is_task_completed` with no limit | 15 s deadline; logs the step, quarantines the task (never joined), repeats the private callable on main behind the loading card |
| `LoadPreparation.resource()` | one unbounded `load_threaded_get_status` loop per caller; dialogue and media look-ahead could request the same path twice | one owner per path; followers share the outcome; on timeout reloads with `CACHE_MODE_IGNORE_DEEP` (does not join the stuck request or its cached dependencies) |
| `AssetGeometry.prepare()` (raw GLB decode) | unbounded status loop; concurrent callers resumed around main-thread scene publication | shared pending record through publication; timeout decodes with the independent `GLTFDocument` path; a late worker result cannot replace the recovered scene |
| `prepare_room()` queue (`_room_busy`) | `while _room_busy` with no limit — an orphaned owner blocks foreground entry forever | deadline plus generation ownership; a superseded coroutine stops at its next yield and reports nothing |
| `await RenderingServer.frame_post_draw` (warm-up and first room draw) | a missed notification (minimised window, device interruption) waits forever | bounded draw wait that keeps pumping frames |

Any deadline opens a session circuit breaker (`PreparationWatchdog.synchronous`):
later preparation goes straight to the synchronous path. Recovery draws the
existing loading card first and pauses the tree (no mission clock advances under
it), restoring the exact prior pause state, also when several recoveries overlap.
Every recovery prints `PREPARATION WATCHDOG {"step": ..., "ms": ...}` and is
written to the probe's JSON (`preparation_recoveries`). No project mutex exists in
the staged construction; the remaining loops are finite per-prop loops.

The 15 000 ms limit is a technical recovery budget (`PreparationWatchdog.timeout_ms`),
not a gameplay value. Normal cache limits are unchanged (64 resources, 16 scenes);
only paths whose abandoned request is still outstanding are pinned until the
reaper consumes the late result.

Files: `game/scripts/loading/preparation_watchdog.gd` (new), `load_preparation.gd`,
`resource_job.gd`, `game/scripts/asset_geometry.gd`, `campaign/chapter1_campaign.gd`;
minimal edits outside the owned paths: `player/locomotion_clips.gd` (step name),
`player/player_controller.gd` (does not rejoin an abandoned tuning request),
`main.gd` (uses the already-prepared title environment). This round also guards
`prepare_room()` so a superseded owner can no longer set the campaign's `failed`
message after a newer owner has taken the queue.

## Limits

The original 17-minute stall was never reproduced, so it is not traced to one
specific wait. Every application-level wait that could hang is now bounded and
recovery is proven with genuinely stuck jobs; ten clean probes are stability
evidence, not proof that an intermittent engine deadlock is impossible. The
watchdog cannot interrupt a native call that blocks the main thread itself, nor
cancel a permanently deadlocked engine thread (it is quarantined and may still
delay engine shutdown). Recovery can produce one long frame, covered by the card.
