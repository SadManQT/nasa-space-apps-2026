## Ramim M1-08 integration

Subscribe to `Chapter1Campaign.p01_panel_requested(view: Dictionary)`. A nearby physical USE emits this signal with no commit, resource spend, flag or receipt. The panel owner supplies presentation and accessible selection controls; until M1-08 lands, the runtime only requests that panel.

Read/reopen: `campaign.p01_view(target_id)` (or `route.p01_view(target_id)`) returns detached dictionaries: `accepted`, `contract_version`, `target_id`, `action`, `scene_id`, `profile`, `state`, `completion`, `missing_flags`, `prerequisite_reason`. Targets outside the current scene reject. Required flags derive from the actual selected target, including cross-scene planting prerequisites; query never focuses or changes the dispatcher.

Preview: `campaign.forecast_target(target_id, selected_payload)` reconstructs an isolated session and returns `accepted`, `input_revision`, Director `query` and projected `p01` view. It grants no live evidence, writes no saves and spends no resource. Keep panel choices locally; closing/cancelling needs no commit or restore. Existing route focus/use/preview/cancel methods remain available for controlled adapters.

Confirm: `campaign.perform_target(target_id, selected_payload)` rechecks physical room/range/line of sight and submits through the existing route dispatcher and Director. If the panel pauses gameplay, use the existing campaign pause/resume flow to resume before confirmation, as the Mission Table does. Reflect the returned result and refresh the read-only view. Do not fill successful payload defaults when the user has made no selection.

| Target / action | Required selected payload |
|---|---|
| `calibrate_probe` / `set_zero` | `{reference: "dry", raw_reading: 10, calibrated_reading: 0}` |
| `span_probe` / `set_span` | `{reference: "wet", raw_reading: 110, calibrated_reading: 100}` |
| `recheck_probe` / `recheck` | `{dry_reading: 0, wet_reading: 100}` |
| `plant_alo` / `plant_alo` | `{cassette: "alo", seed_count: 1}` |
| `plant_tara` / `plant_tara` | `{cassette: "tara", seed_count: 1}` |
| `water_alo`, `water_tara` | `{moisture: <finite number, 40 through 60 inclusive>}`; fractional in-band values are retained |
| `inspect_packet`, `label_alo`, `label_tara`, `seal_alo`, `seal_tara` | Explicit corresponding action confirmation; no numeric payload required |

Calibration accepts numeric readings only, not strings, booleans, containers, missing values or infinities/NaN. Incorrect calibration/order/seed placement/water gives retry feedback before Director commit. Flooding does not kill or water the plant; the player can adjust the local selection and retry. Both route and adapter moisture=50 fallbacks were removed.

Command identity is the gate's stable `physical:<target_id>`; P-01 rejects cross-target `_command_id` and confirm overrides before any Director receipt lookup. Adapter receipts are `p01:<target_id>`. Replaying an already committed action returns its receipt without another spend or planting operation. Legacy integer moisture saves and JSON-decoded numeric seed counts still load; fractional readings remain intact.

`game/tools/support/p01_input_fixture.gd` is **test/capture only**. Existing Chapter 1/P-02 fixtures now submit explicit witness choices; production never imports it. Their original assertions, including the incoming hint-close checks, remain.
